# 区分上下文规格（固定 `K/M`）与累计统计（`Display Unit System`）双展示口径

在同一仪表盘中，上下文窗口水位（如 `302.4K / 512.0K`）、构成拆解与单轮载荷直接对应大模型公开规格（`128K` / `200K` / `512K` / `1M`），开发者对 `K` / `M` 具备精确的工程直觉；而跨轮累加的会话总消耗、缓存累计节省、日/周/月/年 `Usage Ledger` 与套餐积分上限动辄达到千万甚至数亿量级，中文用户阅读 `13.21M` 或 `1.25B` 需要反复心算折合“万/亿”。因此，Token Lens 有意将两类指标拆分为不同展示口径：上下文窗口、构成明细、规则预算、工具上下文及单轮瞬时指标固定采用 `K / M`，仅对累计与周期统计类数值启用可配置的 `Display Unit System`（中文默认 `万 / 亿`，支持切回 `K / M / B`）。

## Considered Options

- **全盘统一替换 `K/M/B` 为 `万/亿`**：实际界面验证显示，`512K` 变成 `51.2万`、迷你构成条出现 `4,930` 与 `1.5万` 混排，反而削弱了与模型上下文规格及行业文档的对应感。
- **全盘维持国际单位 `K/M/B`**：导致 `1,321万`、`1,065万` 等大额统计仍显示为 `13.21M`、`10.65M`，国内用户难以一眼感知百万/千万/亿级消耗规模。
- **按指标语义拆分口径（窗口与单步固定 `K/M`，统计类适用 `万/亿`）**：兼顾上下文工程可读性与大额统计的中文量级直觉。

## Consequences

- 同一面板视图与一键复制 `Markdown` 摘要中会同时存在 `K/M`（上下文行）与 `万/亿`（累计消耗与缓存节省行），属于有意为之的语义分层而非格式遗漏。
- 设置项必须明确命名为“统计展示单位制”（`Stats Display Units`），避免用户误以为切换后也会改变上下文水位单位。
- 所有保留 `K/M` 的上下文数字悬停展示精确整数（`302,400 tok`），统计类数字悬停同时展示精确整数与另一套单位制对照（`13,210,346 tok · 13.21M`）。
